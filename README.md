# 多 Agent 群聊房间

10 个不同人设的 Agent 在一个网页聊天室里共享同一份聊天记录，互相对话。
每条新消息后，每个 Agent **自主判断**是否想接话；上一位发言者可以**提名**下一位发言者，
提名优先，否则按发言意愿加权随机。人类（主持人）可随时插话。

- 设计基线（目标/范围/边界/验收标准）：[docs/plan.md](docs/plan.md)
- 技术形态：零依赖 Node.js（ESM）+ 原生 `node:test`；OpenAI 兼容 LLM 接口；SSE 推送；JSONL 持久化。

## 快速开始

```bash
# 1. 配置（均可选，默认值面向本机已配置的 StepFun 接口）
cp .env.example .env

# 2. 启动
npm start
# 打开 http://localhost:3210

# 3. 测试
npm test
```

### 配置项

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3210` | HTTP 端口 |
| `LLM_BASE_URL` | `https://api.stepfun.com/step_plan/v1` | OpenAI 兼容接口地址 |
| `LLM_API_KEY` | 取 `STEP_API_KEY` | API Key |
| `LLM_MODEL` | `step-5-preview` | 发言模型 |
| `LLM_DECISION_MODEL` | `step-3.5-flash` | 决策模型（轻量、低温） |
| `LLM_SPEAK_MAX_TOKENS` / `LLM_DECISION_MAX_TOKENS` / `LLM_SUMMARY_MAX_TOKENS` | `3000` / `2000` / `3000` | 推理模型的推理 token 也占配额；不足时客户端自动按 4 倍扩容重试（上限 16000，最多 2 次） |
| `LLM_MAX_CONCURRENCY` | `6` | 上游并发上限（StepFun 为 8，留余量防 429） |
| `MAX_AGENT_MESSAGES_PER_TURN` | `0`（不限） | 每轮 Agent 消息预算；正整数才启用 |
| `URGE_THRESHOLD` | `4` | urge 低于该值视为不想发言 |
| `MAX_PER_AGENT_PER_TURN` | `0`（不限） | 单个 Agent 每轮发言次数上限 |
| `MAX_HISTORY` / `DECISION_HISTORY` | `30` / `16` | 发言/决策时下发的历史窗口 |
| `MESSAGE_DELAY_MS` | `900` | 两条 Agent 消息间的节奏间隔 |
| `DATA_DIR` | `./data` | JSONL 持久化目录 |

## 架构

```
src/
  domain/     领域规则（不依赖框架/LLM/UI）
    personas.js   10 个人设（性格、风格、关注领域、禁忌）
    room.js       聊天室聚合：共享历史、"谁能发言"的不变量
    speaking.js   决策解析、下一位发言者选择（纯函数，随机源可注入）
    prompt.js     人设→提示词、输出协议
  llm/        OpenAI 兼容客户端（并发闸门、重试、退避）
  app/        用例编排：回合循环、插话检查点、失败降级、事件流
  server/     HTTP + SSE + 静态页（只做协议转换）
  store/      JSONL 追加式持久化
```

分层原则：领域层不知道 LLM 的存在，LLM 层不知道房间，server 只做协议转换。
测试用假 LLM 驱动完整回合，不发真实请求。

## 循证与总结

- **有目标的讨论**（输入框发送，`mode: 'targeted'`）：发言提示词注入“事实与数据纪律”——
  涉及事实、数据、比例、趋势或案例时必须给出可核查来源（机构/报告名 + 年份，如
  “据 Gartner 2024 年报告”），没有把握就明说“我没有可靠数据”，禁止编造数字或虚构引用；
  决策提示词同时把“有数据或可靠依据可以补充”列为高意愿信号。
- **自由讨论**（顶栏“自由讨论”按钮，`mode: 'free'`）：不注入循证要求，避免闲聊也被迫引用。
- 模式跟随最近一条人类消息，Agent 发言不改变模式。
- **总结讨论**：输入框上方的按钮，对整段讨论生成 300 字以内摘要（保留关键数据及出处），
  以系统消息形式入历史、可跨刷新保留，但被所有 Agent 的上下文窗口过滤，不参与调度。

## 发言调度规则

1. 人类消息或"自由讨论"开启一轮。**默认不设条数上限、不设待机**：无人想发言时也会
   兜底选中意愿最高者接话，一轮持续到被暂停、被清空、人类插话重开，或预算耗尽
   （配置 `MAX_AGENT_MESSAGES_PER_TURN` 正整数才启用预算）。
2. 每轮迭代：对所有候选 Agent 并行发起"是否想接话"的轻量决策（want + urge 0-10 + 理由）。
   候选 = 排除上一句发言人（禁止连庄）、排除本轮已达发言次数上限者（默认不限）。
3. 选中顺序：**上一位发言者的有效提名 > 意愿加权随机（权重 urge²）> 无人想发言时兜底选意愿最高者**
   （决策调用失败的 Agent 不参与兜底，全部失败才结束回合）。
4. 人类插话是检查点：回合在下一次决策前消费该消息并重开一轮，Agent 基于新上下文重新评估。
5. 失败降级：单个决策失败 → 该 Agent 本轮沉默；发言失败 → 跳过并计数，连续 3 次失败才中止本轮。
6. 失控刹车只有四个：随时暂停、清空记录、配置预算、连续 3 次发言失败。
   房间没有自然停顿点，这是刻意选择——发言意愿阈值只影响选谁，不停轮。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 房间快照（成员、消息、状态） |
| `GET` | `/api/events` | SSE 事件流（message / agent_status / turn_* / error） |
| `POST` | `/api/messages` | 主持人发言并触发一轮；`mode`: `targeted`（默认）/ `free` |
| `POST` | `/api/summary` | 生成本轮讨论总结（系统消息） |
| `POST` | `/api/pause` | `{ "paused": true }` 暂停/继续 |
| `POST` | `/api/reset` | 清空历史（同时中止进行中的回合） |

## 验收步骤

```bash
npm test                      # 48 项单元/编排测试
npm start                     # 启动后在浏览器操作：
```

1. 页面展示 10 位成员；输入框发送消息后，Agent 自主接话，发言内容呼应此前的共享历史。
2. 观察一轮自主对话：无同一 Agent 连续发言；状态栏只出现"讨论中/已暂停"，房间不会自行进入待机。
3. 点击"暂停"后调度停止，"继续"后恢复。
4. 杀掉进程重启，历史消息从 `data/rooms/main.jsonl` 恢复（启动日志打印"已恢复 N 条历史消息"）。

## 已知边界

- 单房间、无用户系统；上下文是"最近 N 条"滑动窗口，不做长期记忆检索。
- 推理模型下单条约 15-25 秒（10 路排队决策 + 生成），属预期成本。
- Agent 输出的 `@提名` 只接受名册内名字，其余忽略（防提示词注入）。
