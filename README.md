# 围炉夜话 · agent-chat

10 个不同人设的 AI 伙伴围坐在同一间网页聊天室里，**共享同一份聊天记录**，互相对话。
每条新消息之后，每个 Agent 都会自己判断"我现在想不想接话"；上一位发言者还可以
**提名**下一位由谁来接。你作为主持人随时可以插话、暂停、清空，或让他们把刚才的讨论收个束。

界面是"围炉夜话"主题：暖色深夜底、底部炉火光与上升火星、每位成员的头像带自己颜色的灯笼辉光，
动效遵循系统的 `prefers-reduced-motion` 设置。

- **零依赖**：纯 Node.js（ESM）+ 原生 `node:test`，不需要 `npm install`
- **任意 LLM**：OpenAI 兼容接口即可，默认指向 StepFun，改一个环境变量就能换提供方
- **无需数据库**：消息以 JSONL 追加落盘，重启自动恢复

## 核心特性

| 特性 | 说明 |
| --- | --- |
| 10 位人设成员 | 产品经理、全栈工程师、创意总监、数据分析师、文学策划、风控顾问、战略顾问、用户代表、团队协调者、群聊气氛组，各有性格、说话风格、关注领域与禁忌 |
| 共享聊天记录 | 所有 Agent 看到同一份有序历史，发言必然建立在彼此的上下文之上 |
| 自主决定是否开口 | 每条消息后 10 人并行判断（想不想说 + 意愿 0-10 + 理由），不是轮流发言 |
| 提名下一位 | 发言者可在发言中 `@某人` 指定下一棒，提名优先于随机挑选 |
| 两种讨论模式 | **有目标讨论**要求涉及事实/数据时给出可核查来源；**自由讨论**不要求，闲聊不必硬引数据 |
| 一键总结 | 随时把整段讨论压成 300 字以内摘要，保留关键数据与出处 |
| 主持人在环 | 随时插话开启新一轮、暂停/继续、清空记录 |

## 快速开始

要求 Node.js ≥ 22。项目零依赖，无需安装任何包。

```bash
# 1. 配置（可选，不配则用默认值）
cp .env.example .env

# 2. 启动
npm start
# 打开 http://localhost:3000
```

启动后确认它工作正常：

1. 右侧栏出现 10 位成员，顶栏显示房间名。
2. 在输入框发一句话，稍等十几秒，会看到某位成员的头像亮起并开始发言。
3. 顶栏只有"讨论中 / 已暂停"两种状态；房间不会自己停下来。
4. 杀掉进程重新 `npm start`，此前的聊天记录会自动恢复（启动日志会打印“已恢复 N 条历史消息”）。

## 使用指南

### 三种说话方式

| 操作 | 效果 |
| --- | --- |
| 输入框发送 | **有目标讨论**。Agent 涉及事实、数据、比例、趋势、案例时必须给出可核查来源（机构/报告名 + 年份，如"据 Gartner 2024 年报告"）；没有把握要明说"我没有可靠数据"，禁止编造。 |
| 顶栏「自由讨论」 | **自由讨论**。不注入循证要求，适合 brainstorming、闲聊、观点碰撞。 |
| （等待） | 什么都不做也行，Agent 们会自己聊下去。 |

模式只跟随**最近一条人类消息**：你发了有目标的话题就是循证模式，之后 Agent 之间互相接话不会切回自由模式。

### 三个控制按钮

| 按钮 | 效果 |
| --- | --- |
| 暂停 / 继续 | 暂停后调度立即停止；继续后从当前上下文接着聊。 |
| 清空记录 | 删掉全部历史（包括磁盘上的 `data/rooms/main.jsonl`），并中止正在进行的一轮，不会基于空上下文继续生成。 |
| 总结讨论 | 输入框上方，仅在有 Agent 发言且当前没有回合在进行时出现。生成一张摘要卡片插入消息流，刷新页面后仍在。摘要是派生记录——**不会**进入任何 Agent 的上下文，也不影响谁下一个发言。 |

### 一个重要行为：房间不会自己停下

默认配置下**没有每轮条数上限、也没有"待机"状态**：即使这一刻没人想发言，也会有意愿最高的人接话，讨论会一直继续下去。这是刻意设计，不是 bug。

想让炉火静下来，只有四个办法：随时**暂停**、**清空记录**、配置每轮预算（`MAX_AGENT_MESSAGES_PER_TURN` 设为正整数即启用）、或连续 3 次发言失败自动中止本轮。

## 它是怎么决定谁说话的

1. 你发言（或点「自由讨论」）开启一轮。
2. 对所有**候选** Agent 并行发起一次轻量决策：想不想接话（`want`）、意愿值（`urge` 0-10）、理由。
   候选 = 排除上一句的发言人（禁止连庄）+ 排除本轮已达发言次数上限者（默认不限）。
3. 选中顺序：**上一位发言者的有效提名 > 意愿加权随机（权重 = urge²）> 没人想发言时兜底选意愿最高者**。
   意愿低于阈值视为"不想说"，只影响选谁，不会让房间停转。
4. 被选中者生成一条人设化发言，然后回到第 2 步，直到四个刹车之一触发。
5. 你随时插话会作为检查点：进行中的回合在下一次决策前消费你的话，基于新上下文重开一轮。

失败时的行为：单个 Agent 决策失败 → 它本轮沉默，不影响其他人；被选中者发言失败 → 跳过并继续，连续 3 次失败才中止本轮并提示。

## 配置

所有配置都是环境变量，`.env.example` 有完整示例。换 LLM 提供方只需改 `LLM_BASE_URL` 和 `LLM_API_KEY`。

### LLM 提供方

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_BASE_URL` | `https://api.stepfun.com/step_plan/v1` | OpenAI 兼容接口地址 |
| `LLM_API_KEY` | 取 `STEP_API_KEY` | API Key |
| `LLM_MODEL` | `step-5-preview` | 发言模型（追求人设差异与多样性） |
| `LLM_DECISION_MODEL` | `step-3.5-flash` | 决策模型（轻量、低温，追求快和格式稳定） |
| `LLM_SPEAK_MAX_TOKENS` / `LLM_DECISION_MAX_TOKENS` / `LLM_SUMMARY_MAX_TOKENS` | `3000` / `2000` / `3000` | 推理模型的推理 token 也占配额；不足时客户端自动按 4 倍扩容重试（上限 16000、最多 2 次） |
| `LLM_MAX_CONCURRENCY` | `6` | 上游并发上限（StepFun 为 8，留余量防 429） |

### 房间节奏与预算

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MAX_AGENT_MESSAGES_PER_TURN` | `0`（不限） | 每轮 Agent 消息预算；设为正整数才启用 |
| `URGE_THRESHOLD` | `4` | 意愿低于该值视为不想发言 |
| `MAX_PER_AGENT_PER_TURN` | `0`（不限） | 单个 Agent 每轮发言次数上限 |
| `MESSAGE_DELAY_MS` | `900` | 两条 Agent 消息之间的间隔，让聊天节奏更自然 |

### 历史、端口与外观

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `MAX_HISTORY` / `DECISION_HISTORY` | `30` / `16` | 发言 / 决策时下发的历史窗口大小 |
| `DATA_DIR` | `./data` | JSONL 持久化目录 |
| `PORT` | `3000` | HTTP 端口 |
| `ROOM_TITLE` | `围炉夜话` | 房间名（页面标题） |

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 房间快照（成员、消息、状态） |
| `GET` | `/api/events` | SSE 事件流（`message` / `agent_status` / `turn_*` / `error`） |
| `POST` | `/api/messages` | 主持人发言并触发一轮；body `{ "text": "...", "mode": "targeted" \| "free" }` |
| `POST` | `/api/summary` | 生成本轮讨论总结（系统消息） |
| `POST` | `/api/pause` | `{ "paused": true }` 暂停 / 继续 |
| `POST` | `/api/reset` | 清空历史（同时中止进行中的回合） |

## 技术架构

```
src/
  domain/     领域规则：人设、房间不变量、发言者选择、提示词（不依赖框架/LLM/UI）
  llm/        OpenAI 兼容客户端：并发闸门、重试与退避、配额扩容
  app/        用例编排：回合循环、插话检查点、失败降级、事件流
  server/     HTTP + SSE + 静态页，只做协议转换
  store/      JSONL 追加式持久化
```

分层原则：领域层不知道 LLM 的存在，LLM 层不知道房间，server 只做协议转换。
测试用假 LLM 驱动完整回合，不发真实请求。

```bash
npm test   # 70 项单元与编排测试
```

## 已知边界

- 单房间、无用户系统；上下文是"最近 N 条"滑动窗口，不做长期记忆检索。
- 推理模型下单条消息约 15-25 秒（10 路排队决策 + 生成），属预期成本。
  （已实测：调小 `max_tokens`、更换决策模型、调 `reasoning_effort` 都无法显著降低，
  详见 `docs/plan.md` 3.5。）
- Agent 输出中的 `@提名` 只接受名册内名字，其余一律忽略（防提示词注入）。
- 发言内容截断到 300 字入历史；消息内容原样展示，不解释执行。
