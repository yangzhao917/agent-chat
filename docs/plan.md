# 多 Agent 群聊系统 · 实施基线

> 依据 AGENTS.md 第 2 条：实质实现前记录目标、范围、关键边界与验收标准。实现、测试、文档均以本文件为准。

## 1. 目标

一个网页聊天室，10 个不同人设的 Agent 共享同一份聊天记录并互相对话：

- **共享上下文**：所有 Agent 与人类看到同一份有序消息历史，任何发言都基于最近上下文生成。
- **自主发言**：每条新消息后，每个 Agent 独立判断"我现在是否想接话"（want + urge 0-10 + 理由），由调度器决定谁发言。
- **自主提名**：发言者可在发言中提名（`@名字`）下一位发言者，提名在同等条件下优先于随机挑选。
- **人类在环**：人类（主持人）可随时插话，插话会开启新一轮并让所有 Agent 重新评估。
- **循证发言**：有目标的讨论（人类主动提出的话题）要求 Agent 涉及事实/数据时给出可核查来源
  （机构/报告名 + 年份），不确定须明说，禁止编造；自由讨论不注入该要求。
- **讨论总结**：可随时对整段讨论生成摘要（保留关键数据及出处），作为系统消息入历史，
  但不参与任何 Agent 的上下文。

## 2. 范围

做：
- 10 个固定人设 Agent（见 `src/domain/personas.js`），人设驱动发言风格与发言意愿。
- 回合制调度器：决策回合（并行询问全部候选）→ 选中一名发言 → 循环，直至无人想发言或达到本轮预算。
- 网页 UI：消息流、成员列表、思考/发言状态、话题输入、自由讨论、讨论总结、暂停/继续、清空。
- 持久化：房间消息以 JSONL 追加式落盘，重启后可恢复（消息即事实来源）。
- 单元测试 + 基于假 LLM 的编排测试；README 记录运行与验收步骤。

不做（明确排除，避免范围蔓延）：
- 不做用户系统/多房间隔离/权限（单房间演示）。
- 不做向量检索式长期记忆，上下文就是"最近 N 条消息"的滑动窗口。
- 不引入 Web 框架与数据库：零依赖 Node ESM + `node:test`；持久化用 JSONL（单进程服务器、只追加日志，无需外部数据库服务，符合 AGENTS.md 第 6 条"不假定本机端口或容器存在"）。
- 不做语音、图片等多模态。

## 3. 关键边界与取舍

### 3.1 LLM 提供方（关键假设）
本机环境已配置 StepFun（`STEP_API_KEY`，`https://api.stepfun.com/step_plan/v1`，OpenAI 兼容 `/chat/completions`，已实测可用）。
默认：发言用 `step-5-preview`，决策用更轻的 `step-3.5-flash`；均可用环境变量覆盖（`LLM_MODEL` / `LLM_DECISION_MODEL` / `LLM_BASE_URL` / `LLM_API_KEY`）。
接入层只依赖 OpenAI 兼容协议，换提供方只改配置不改代码。

### 3.2 调度规则（领域规则，`src/domain/speaking.js`）
1. 每轮（由人类消息或"自由讨论"触发）**默认不设条数上限**（`MAX_AGENT_MESSAGES_PER_TURN=0`）：
   一轮持续到无人想发言、被暂停或人类插话重开。设为正整数则启用预算保护。
2. 候选 = 未处于冷却的 Agent：上一句不是它说的（禁连庄）、本轮发言次数未达上限
   （`MAX_PER_AGENT_PER_TURN=0` 默认不限）、房间未暂停。
3. 选择顺序：**上一位发言者的有效提名 > 意愿加权随机（权重 = urge²）> 无人想发言时兜底选意愿最高者**。
   - urge < `URGE_THRESHOLD`（默认 4）视为不想发言。
   - 提名无效（指向自己、已出局者、人类、不在名册）时降级为加权随机。
   - **不设待机状态**：无人想发言时也按“意愿最高者”接话（忽略 want 与阈值），
     房间不会因冷场而停转；决策调用失败（`failed`）不属于“选择沉默”，不参与兜底，
     全部失败时才结束回合。
4. 人类插话是检查点：进行中的回合在下一次决策前消费该消息，重置预算与发言记录（新一轮），Agent 基于含人类消息的新上下文重新评估。
5. 循证模式跟随最近一条人类消息的 `meta.mode`：`targeted`（默认，输入框发送）注入循证要求，
   `free`（“自由讨论”按钮）不注入；Agent 发言不改变模式。
6. 总结消息（`kind: 'system'` 且 `meta.summary`）是派生记录：入历史与持久化，但被所有
   Agent 的上下文窗口过滤掉，也不抢占发言权。

### 3.3 LLM 适配层的配额扩容
推理型模型的推理 token 占用 `max_tokens` 配额，吃满时 `finish_reason=length` 且 `content` 为空
（实测踩坑：决策配额 200、总结配额 1500 都因此失败过）。客户端策略：遇到 `length` 时
按 4 倍扩容重试，最多 2 次、上限 16000 token；扩容后仍失败才向上层抛错。
该行为由假 fetch 的测试锁定。

### 3.4 失败降级（不允许"静默猜测"）
- 单个 Agent 决策调用失败/输出不可解析 → 该 Agent 本轮视为沉默，记录原因，不影响其他 Agent。
- 被选中者发言调用失败/输出不可解析 → 消耗其本轮额度并跳过，继续调度；连续失败 3 次则结束本轮并推送 error 事件。
- LLM 输出非严格 JSON 时尽力解析（剥离代码块围栏、截取首尾花括号）；仍失败则按上述降级处理，不用猜测内容冒充 Agent 发言。

### 3.5 等待时间的实测结论（不再展示思考过程）
实测（本机 StepFun）：一条 Agent 消息端到端约 33s = 决策阶段 ~12s（10 个并行轻量决策，
单个 ~5.5s，受并发闸门 6 限制分两波）+ 发言阶段 ~20s（其中约 17s 是推理 token，
正文仅约 100 字）+ 节奏间隔 0.9s。

已实测无效的提速手段，记录在此避免重复尝试：
- 调小 `max_tokens`：决策 600/1200/2000 均为 5~13s；发言压到 1200 反而要 49s——
  推理长度不受该参数约束，压小只会触发 4 倍扩容重试，更慢。
- 更换决策模型：`step-3.5-flash` 5.8s / `step-3.5-flash-2603` 5.5s / `step-3.7-flash` 6.4s，无差异。
- `reasoning_effort: low`：决策 5.8→5.0s、发言 20.4→18.9s，仅约 10%。
- 提高并发到 8：上游上限即 8，零余量易触发 429 退避，收益仅 ~1s。

曾实现过"流式输出思考过程"（把 `reasoning_content` 实时显示成虚线气泡）来降低感知等待，
**用户明确要求不展示思考过程，该实现已完整回退**：客户端恢复非流式 `speak`，
前端不再有 `agent_reasoning` 事件与思考气泡，测试回到 70 项。
流式代码没有保留——不展示就没有存在意义，留着只是死分支。

若后续仍要缩短等待，剩下两条路都会改变产品特性，需先确认：
1. 发言模型换成 `step-3.7-flash`（实测单条 20s→6s），代价是发言质量下降、循证可靠性变差。
2. 上一位发言者的提名有效时跳过决策阶段（省 ~12s），代价是削弱"10 位 Agent 自主判断是否接话"
   这一核心行为——提名本就更优先，跳过决策不改变结果，但会让自主判断大部分回合不再发生。

### 3.6 成本与安全
- 每条消息触发至多 10 次并行轻量决策调用 + 1 次发言调用。
- **默认无限额度 + 不设待机是用户明确要求的选择**：房间没有任何自然停顿点，
  刹车只有四个——随时暂停、清空记录、配置 `MAX_AGENT_MESSAGES_PER_TURN`（正整数即启用）、
  连续 3 次发言失败。决策 prompt 中"宁可少说，不说废话"用于降低低质量发言比例，
  但不作为停止条件。这两条代码路径均有测试覆盖。
- LLM 输出长度截断（发言 ≤300 字进历史）、人数与轮次上限硬编码为默认值并在测试中锁定。
- 提示词注入边界：Agent 输出中的 `next` 只能取名册内的名字，其余一律忽略；`content` 原样入库展示，不解释执行。

## 4. 验收标准

1. `npm test` 全部通过（覆盖：调度选择规则、房间不变量、回合编排、LLM 客户端重试与解析、持久化往返）。
2. `npm start` 后浏览器可用：10 个 Agent 人设展示齐全；人类发消息后 Agent 自主接话，且接话内容引用/呼应此前的共享历史。
3. 观察一轮自主对话：不存在同一 Agent 连续发言；状态栏只出现"讨论中/已暂停"，
   房间不会自行进入待机；配置预算后不超过预算。
4. 有目标讨论时，Agent 发言提示词含循证条款；自由讨论时不含（测试锁定）。
5. 点“总结讨论”生成摘要卡片，刷新页面后仍在；摘要不出现在后续任何 Agent 的上下文里。
4. 杀进程重启后历史消息从 JSONL 恢复。
5. 用假 LLM 的测试可证明：所有 Agent 的提示词中都包含此前的共享消息历史（即"共享聊天记录"可验证）。

## 5. 开源发布（基线）

目标：以同名仓库 `agent-chat` 公开发布到 GitHub，使外部读者可 clone 后直接跑起来。

范围：
- 仓库卫生：移除误入库的 `.DS_Store` 并加入 `.gitignore`；修正 README 中过时的测试数量。
- 补充 `LICENSE` 与 README 的 License 章节。
- 说明 LLM 提供方可替换（默认指向 StepFun，但任意 OpenAI 兼容端点均可）。

关键边界：
- **不得提交任何密钥或本地数据**。已核实：`data/`、`.env` 从未入库，全 12 个提交的历史中
  无 `sk-` 形态密钥、无 `STEP_API_KEY=` 赋值。发布前重新扫描一次作为验收。
- LICENSE 选型用户未指定，暂用 **MIT**（最常见、限制最少）；这是可后续替换的一次性决策，
  需在交付时明确告知用户。
- 不引入 CI、Issue 模板、贡献指南等范围外内容；不做 npm 发布，`package.json` 的
  `private: true` 保留（仅阻止误发 npm，不影响 GitHub 开源）。

验收标准：
1. `git ls-files` 中无 `.DS_Store`、无 `.env`、无 `data/` 下任何文件。
2. 全历史提交中无密钥形态字符串。
3. `npm test` 70 项通过；README 的测试数量与实际一致。
4. 仓库在 GitHub 上为 public，`git remote -v` 指向同名仓库，`main` 分支已推送。
